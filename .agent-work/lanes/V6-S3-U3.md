- **Design**: no migration. A venture is a `bots` row (kind `lead`, `repos=[repo]`, `tools=LEAD_SCOPES`) plus one `bot_tokens` row holding only `sha256(token)`, plus an `add_venture` event carrying the venture name, brief and idempotency key (never the token). Create and rotate each run in one Postgres transaction under `pg_advisory_xact_lock`, re-checking STOP ALL (`control` row `for share`) and duplicates inside the lock. Rotation deletes the old token rows (Resume un-suspends every row, so suspending is not revocation).
