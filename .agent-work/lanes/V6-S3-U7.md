# V6 Stage 3 unit 7 — version-upgrade check and rollback on tap

- **Owns**: new `hq/upgrade-check.ts` (open checks, runner, grader, decision, approval executors), `hq/approval.ts` (executors for `model_upgrade` → start check, `upgrade_rollback`, `council_upgrade`), `hq/pins.ts` (`connectorTick` gains a fail-soft `upgrade` step after pins; switch rows never count as the daily check), `hq/connector.ts` (`callConnectorTool` takes a trusted internal-only `modelOverride` for the `hq-upgrade` bot), `hq/connector-store.ts` + `hq/connector-pg.ts` (internal bot, `model_outcomes`, atomic decision, conditional pin switch, events by action, resolution ids), `hq/server.ts` (tick wiring), `hq/bundled-assets.ts` + `scripts/bundle-hq.mjs` (saved tasks ship in the bundle), `scripts/check-briefs.sh` (scans saved tasks), `config/upgrade-tasks/<family>/*.md` (5 per family), tests `tests/unit/upgrade-check.test.ts`, `tests/integration/upgrade-check.test.ts`.
- **Out of scope**: migrations (none needed), new screens or Needs-you label copy, Checker grading of upgrade runs (later), the sandbox repo itself (owner action), live data.
- **Done-command**: `npm run typecheck && npm run lint && npm test && npm run check:vendor && npm run check:briefs && npm run check:bundle && npm run scan:secrets && npm run test:integration` (every step with live DB URLs and API keys unset; integration on local Postgres 16).
- **Design**: owner taps Approve on a `model_upgrade` card → an `upgrade_check_started` event (check id = approval id). Each minute tick (reconcile → fleet → pins → upgrade, each fail-soft) advances open checks: STOP on → nothing; no `DEXTER_UPGRADE_SANDBOX_REPO` → one `sandbox_repo_missing` post, check waits; otherwise the internal `hq-upgrade` bot (kind `other`, no token) launches each saved task on the incoming version, and on the current pin when that task has no result yet, through `callConnectorTool` (`reserveLaunch` caps, STOP, idempotency key `upgrade:<family>:<version>:<task>`). Finished runs are graded (default: Cursor FINISHED = pass) into `model_outcomes`. When every run has an outcome: incoming pass rate ≥ current → worker family: pin switches + notice + `upgrade_rollback` card; CEO family (gpt-sol): `council_upgrade` card. Else the old pin stays and the result is posted.
