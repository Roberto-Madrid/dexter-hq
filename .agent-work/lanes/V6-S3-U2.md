# V6 Stage 3 unit 2 — launches carry repo + pinned model

- **Owns**: `kernel/types.ts` (`RunSpec.repo/startingRef/modelId`), `adapters/cursor-cloud.ts` (`start()` sends `repos` + `model`, new `listModels()`), new `hq/pins.ts` (daily resolve + tick entry), `hq/connector-store.ts` + `hq/connector-pg.ts` (pin reads/writes on `model_resolutions`), `hq/connector.ts` (`handleLaunch`: resolve repo + pin, refuse `model_held` / `repo_required` / `repo_mismatch`), `hq/server.ts` (`postTick` runs the daily check), `supabase/functions/catalog-sync` (shortcut note only), tests `tests/unit/pins.test.ts`, `tests/integration/pins.test.ts`, fixtures that now seed pins.
- **Out of scope**: `get_context` / `post` / `verify_post` (U4), owner venture endpoints (U3), switching pins on approval (U7 upgrade check), web UI, migrations, live data.
- **Done-command**: `npm run typecheck && npm run lint && npm test && npm run check:vendor && npm run check:briefs && npm run check:bundle && npm run scan:secrets && npm run test:integration`
- **Design**: bots pass a role; the connector maps role → family (role sheet) → pin (latest non-held `model_resolutions` row for the owner) and sends `model: { id }`. No pin → `model_held`, nothing reserved. Repo work sends `repos: [{ url: "https://github.com/<repo>", startingRef? }]`; the repo comes from the call or the request, and `startingRef` is the request's bound branch when there is one. Only `scout` bots may launch without a repo. Follow-ups carry neither: Cursor's follow-up run keeps the agent's repo and model.
- **Daily check**: the per-minute tick calls `resolveDailyPins` once per UTC day per owner. It reads `GET /v1/models`, picks one id per `catalog_match` family (fast/max/preview ignored), and appends one row per family under an advisory lock: the first pin is the baseline, the same version is a `confirmed` row, a new version is a `held` row plus one pending `model_upgrade` approval (a Needs-you card). The held row never becomes the pin. Cursor unreachable → nothing written, pins kept, an event every try and one alert post per day, retried at most hourly.
