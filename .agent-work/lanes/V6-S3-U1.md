# V6 Stage 3 unit 1 — caps you can trust

- **Owns**: `hq/chat.ts` (drop the direct dispatch), `hq/tick.ts` → `legacy/hq/tick.ts`, `hq/server.ts` (`postTick` → `reconcileConnector`), new `hq/reconcile.ts`, `hq/connector.ts` (`handleLaunch` reserves atomically, `agent_status` writes the terminal state back, `request_council` weekly seat cap), `hq/connector-store.ts` + `hq/connector-pg.ts` (`reserveLaunch`, `setAgentStatus`, `reserveCouncilSeat`), `adapters/cursor-cloud.ts` (terminal run-state map), `scripts/ensure-integration-db.mjs` (apply `0007`/`0008` locally), `vercel.json` (Q6: only `main` deploys), tests `tests/unit/caps.test.ts`, `tests/unit/reconcile.test.ts`, `tests/integration/connector-caps.test.ts`, `tests/unit/g3.test.ts` imports.
- **Out of scope**: launch repo/model (U2), roster and Add venture (U3), post rules and scopes (U4), `update_request` (in-flight PR), migrations, live data.
- **Caps (owner defaults, Q1)**: 3 global agents (6 surge by approved tap), 2 per repo for every venture, 5 launches per request, 40 Council seat runs per 7 days. No per-venture override.
- **Done-command**: `npm run typecheck && npm run lint && npm test && npm run check:vendor && npm run check:briefs && npm run check:bundle && npm run scan:secrets && npm run test:integration`
- **Design**: the connector is the only launch path. Each launch takes one Postgres transaction with `pg_advisory_xact_lock` and inserts a `reserving` row (unique `(bot_id, idempotency_key)`), so two launches cannot both pass a cap. The per-minute tick (`POST /api/tick-now`) polls active agents and moves them to `finished`/`error`/`cancelled`/`expired` with a conditional update, so a second tick changes nothing.
